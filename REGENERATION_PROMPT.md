# LED-List — ТЗ для повторной генерации приложения

> Это самодостаточный промпт. Вставьте его целиком в новый чат с формулировкой:
> **«Сгенерируй это веб-приложение согласно ТЗ ниже. Начни с проектирования схемы БД и движка ёмкости блока, затем API и CRUD, затем UI. Localhost, демо-данные при первом запуске.»**

---

## 1. Что это

Мультитенантный **SaaS для оператора цифровой наружной рекламы (DOOH)** — управление сетью **LED-экранов**. Аналог системы для билбордов, но переработанный под цифровые экраны: рекламное место продаётся **не как «сторона конструкции на месяц»**, а как **слот в блоке ротации** (плейлисте): доля показов с заданной длительностью ролика и периодом трансляции, по ставке «рублей за секунду ролика в месяц».

Интерфейс на **русском**, валюта **₽**, формат дат **ДД.ММ.ГГГГ**.

## 2. Ключевое отличие от билбордов (обязательно)

1. Нет печати баннера, монтажа, подсветки. Вместо загрузки макета — загрузка **видео/креатива** (mp4, jpg, png, gif) с чтением разрешения и длительности.
2. Один экран показывает **много рекламодателей одновременно** через блок. Продаётся **слот в блоке**: длительность ролика (сек), период дат (от/до), тайм-слот (часть суток). Цена считается от ставки «рублей за 1 секунду ролика за 30 дней»; количество выходов в сутки — производная от блока, а не параметр продажи.
3. **Ёмкость блока**: в любой день сумма длительностей активных роликов на экране не может превышать длину блока (`loop_duration_sec`). Нельзя продать больше, чем вмещает блок.
4. Технические характеристики экрана вместо «формата 6х3»: физический размер (м), разрешение (px), шаг пикселя (P4/P6/P10), яркость (нит), тип (уличный/внутренний), ориентация, длина блока (сек), часы работы.
5. Занятость показывается **не «месяц занят одним клиентом», а как загрузка блока в %** по датам/месяцам.
6. Дополнительно: у экрана есть текстовое поле **«Сторона»** (А/Б — для двусторонних конструкций; у односторонних просто «А»).

## 3. Технологический стек

- **Frontend:** React 18 + TypeScript + Vite, react-router-dom, обычный CSS-файл (без UI-библиотек). Прокси `/api` → бэкенд.
  - Важно для Windows: в `vite.config.ts` указать `server.host: '127.0.0.1'`, `strictPort: true`, прокси на `http://127.0.0.1:3001` (иначе Vite может слушать только IPv6 ::1 и localhost будет недоступен).
- **Backend:** Node + Express + TypeScript (запуск через `tsx`), БД **SQLite** через `better-sqlite3` (схема переносима на PostgreSQL: целочисленные PK, FK, CHECK-ограничения). Пароли — `scrypt` (соль:хеш). Аутентификация — **JWT** (`jsonwebtoken`), срок 12 ч. Загрузка файлов — `multer` на диск в `data/uploads/`.
- **Мультитенантность:** во всех бизнес-таблицах поле `tenant_id`; каждый запрос фильтруется по тенанту из JWT.
- Порты: API **3001**, клиент **5173**. Запуск: `npm run dev` в `server/` и `client/`.
- БД-файл `server/data/led.db` создаётся и наполняется демо-данными при первом старте.

## 4. Роли и доступ

- Ролей две: `admin` и `manager`. Платформенной роли «суперадмин» и раздела «Подписки» нет — система работает как одна компания. Поле `tenant_id` в схеме сохранено: оно изолирует данные и оставляет запас на несколько компаний, но управляется не из интерфейса.
- `admin` — администратор компании: всё в рамках своего тенанта, включая справочники, создание/редактирование/удаление экранов, **свои данные для входа** (Настройки → Мой аккаунт: имя, email-логин, пароль) и **учётные записи менеджеров** (логин с паролем задаёт он же — самостоятельной регистрации в системе нет).
- `manager` — менеджер по продажам: ведёт черновики, брони и продажи, заводит клиентов. **Запрещено**: создавать/править/удалять экраны и фото, удалять платежи, удалять клиентов, видеть подписки и настройки компании, а также **менять уже проданную кампанию** — отменять её, добавлять и удалять слоты (переход из `sold`, `POST/PUT/DELETE` слотов проданной кампании → 403 «Кампания продана…»). Брони и черновики менеджер правит свободно.
- Ограничения проверяются на сервере (`requireRole`, проверка роли по статусу кампании) и одновременно скрываются в интерфейсе, чтобы менеджер не видел заведомо недоступных кнопок: в инвентаре нет карточки «Продано из потенциала» (деньги сети) и кнопок «Изменить»/«Добавить экран»; в карточке проданной кампании нет кнопки отмены, корзин у слотов, а «Добавить слот» заблокирована; в справочнике клиентов нет корзины. Признак роли на клиенте — `isAdmin()` из `api.ts`.

**owners** — id, tenant_id, name, phone, email, comment (владельцы конструкций).
**clients** — id, tenant_id, name, phone, email, address, contacts (JSON-массив контактных лиц), comment.
**managers** — id, tenant_id, user_id (nullable), name, phone, email.

**screens (LED-экран)** — id, tenant_id, code (напр. `GRZLED04001`), name, **side** (текст, А/Б), address, city_id, lat, lng, width_m, height_m, res_w, res_h, pixel_pitch, brightness, screen_type_id, orientation (horizontal|vertical), **loop_duration_sec** (длина блока, по умолч. 60), work_from, work_to, **price_per_sec_month** (цена 1 секунды за 30 дней — основная ставка прайса), tax_regime_id, owner_id, status (active|maintenance|inactive), tags, comment.

**campaigns (кампания/заказ)** — id, tenant_id, number (напр. `2026-041`), client_id, manager_id, created_at, status (draft|reserved|sold|cancelled), reserve_until (nullable), discount_id, discount_percent, production_cost (производство ролика — отдельная услуга вместо монтажа/печати), comment.

**creatives (креатив)** — id, tenant_id, campaign_id, filename, stored_name, mime, size_bytes, duration_sec, width, height, uploaded_at.

**ad_slots (слот размещения)** — id, tenant_id, campaign_id, screen_id, creative_id (nullable), duration_sec, date_from, date_to, plays_per_day, time_slot_id (nullable), price.

**screen_photos (фото экрана)** — id, tenant_id, screen_id (ON DELETE CASCADE), filename, stored_name, mime, size_bytes, sort_order (первое по порядку = главное фото), uploaded_at.

**payments** — id, tenant_id, campaign_id, pay_date, amount, method (bank|cash|card), comment.

**company_settings** — tenant_id (PK), legal_name, inn, address, phone, email, reserve_days (по умолч. 3), columns_config (JSON).

## 6. Ключевая бизнес-логика (движок — самое важное)

### 6.1 Движок ёмкости блока
Модель посуточная. Активными считаются слоты кампаний в статусе `reserved` или `sold`. Для экрана и диапазона дат для каждого дня: `used_sec = Σ duration_sec активных слотов, покрывающих этот день`; `load_pct = used_sec / loop_duration_sec * 100`. Функции:
- `loopLoad(screenId, from, to)` → по дням `{date, used_sec, load_pct}` + `max_load_pct`, `avg_load_pct`, `free_sec`.
- `checkCapacity(screenId, from, to, durationSec)` → влезает ли ролik: для каждого дня `used_sec + durationSec ≤ loop_duration_sec`; иначе `{ok:false, reason}` с перечнем дней переполнения.
- `checkCampaignCapacity(campaignId)` — **агрегатная** проверка перед бронью/продажей: по каждому экрану и дню сумма роликов ЭТОЙ кампании + чужих активных ≤ блок. (Важно: по-слотовая проверка пропускает переполнение собственными роликами кампании — нужна именно агрегатная.)
- `expireReservations()` — снимает просроченные брони (`status='reserved' AND reserve_until < today`) в `cancelled`, освобождая ёмкость. Вызывается в начале GET-хэндлеров списков/расписания.

### 6.2 Калькулятор стоимости — модель «цена секунды за 30 дней»
Базовая ставка экрана — поле **`price_per_sec_month`**: цена ОДНОЙ СЕКУНДЫ ролика при размещении на 30 дней. Пример: ставка 2500 ₽/сек → ролик 10 сек на месяц стоит 25 000 ₽.

`month_price = price_per_sec_month × duration_sec`  (цена ролика за 30 дней)
`base = month_price × (кол-во_дней_периода / 30)`  (пропорция за неполный/длинный период)
`× коэффициент тайм-слота (price_coef)` `× (1 − скидка%/100)` = net;
`налог = net × tax_rate/100` (сверху, для режимов с НДС); `total = net + налог`.
Итог разбивается на «Размещение» и опционально «Производство ролика».

**Количество выходов в сутки на цену не влияет** — оно определяется блоком: ролик показывается один раз за оборот, то есть `plays_per_day = часы_работы_в_секундах / loop_duration_sec`. Это значение считается автоматически, показывается справочно в калькуляторе и сохраняется в слоте; вводить его вручную не нужно.

### 6.3 Статусы кампании (переходы валидируются на сервере)
`draft → reserved | cancelled`; `reserved → sold | draft | cancelled`; `sold → cancelled`; `cancelled → draft`.
При переходе в `reserved`/`sold` — агрегатная проверка ёмкости, при переполнении **HTTP 409**. При `reserved` выставляется `reserve_until = today + reserve_days` (из настроек). Отмена освобождает блок.

## 8. Разделы и навигация (админ-панель, верхнее меню с выпадающими списками)

- **Инвентарь экранов** — таблица с фильтрами. Настраиваемые колонки (чекбоксы, сохранять в localStorage). **Модальный фильтр с несколькими условиями** (поле: код, название/адрес, сторона, город, тип, шаг пикселя, владелец, статус, теги, загрузка ≥/≤, яркость; оператор: содержит/=/≥/≤; можно добавлять несколько условий, чипы применённых фильтров). Колонка **«Загрузка блока»** — индикатор-бар в % (зелёный <70, оранжевый <95, красный ≥95). Колонка **«Сторона»**. Селектор периода для расчёта загрузки.
  - Стиль строк инвентаря: отдельные «плашки» (border-spacing между строками), ячейки по центру, вертикальные разделители, скруглённые углы, код — моноширинный.
  - Кнопки в строке: «Плейлист» (ротация по дням) и «Изменить» (admin).
  - **Выбор строк галочками + «Экспорт в Excel»**. Окно экспорта: имя файла (по умолчанию «Адресная программа - ДД.ММ.ГГГГ»), переключатель «Фото и карта как ссылки», список столбцов галочками (код — обязательный), вкладки годов и галочки месяцев. По каждому выбранному месяцу в файл добавляется колонка с пиковой загрузкой блока и свободными секундами, ячейка заливается по уровню загрузки (зелёный/жёлтый/красный). Если ничего не отмечено — выгружается вся текущая выборка.
  - Ссылка «Карта» ведёт на Яндекс.Карты по координатам; ссылка «Фото» — на карточку экрана в системе. Токен доступа в файл не кладётся: выгрузка может уйти по почте.
  - **Кнопка «Прайс PDF»** рядом с экспортом в Excel открывает окно настроек (галочка «Закрывающая страница со сводкой» и число страниц), затем печатается по странице A4 (портрет) на каждый выбранный экран. Порядок на листе: шапка (компания слева, дата справа) → название экрана крупно и жирно, код мелкой серой подписью под ним, справа плашка «СТОРОНА А» одной строкой → город с адресом → две колонки: слева «Характеристики экрана» (размер, разрешение, тип) и «Блок ротации» (длина блока, выходов в месяц), справа «Стоимость размещения» (плашка: ролик 10 секунд за 30 дней крупной цифрой + ставка за секунду) и «Другие длительности» (5 и 15 сек) → **фотография во всю ширину**, под ней **карта расположения во всю ширину** (оба блока делят остаток страницы пополам) → подвал.
  - **Закрывающая страница со сводкой** (включается галочкой в окне «Прайс в PDF», по умолчанию включена): заголовок «Сводка по подборке», подпись с числом экранов, таблица «№ / Код / Экран и адрес / Сторона / Блок / Цена, 30 дней» (высота строки считается по фактической высоте адреса, длинные адреса переносятся, при переполнении листа таблица продолжается на следующем с повтором шапки), плашка «Итого за размещение на 30 дней» с общей суммой и сноска о том, что цены справочные. Цена строки — та же цифра, что крупно на странице экрана: `calcPrice` для ролика 10 секунд на 30 дней (с налогом). В окне экспорта показывается итоговое число страниц.
  - Шрифт для PDF нужен с кириллицей: встроенные шрифты PDF её не имеют. Подходит `@expo-google-fonts/pt-sans` (полные TTF; у `@fontsource` кириллица и латиница лежат в разных подсетах — для смешанного текста не годится).
  - Шрифт выбирается по приоритету: `PDF_FONT_DIR`/`PDF_FONT_FAMILY` из окружения → фирменный шрифт из системных каталогов (по умолчанию ищется `MazzardM`) → встроенный PT Sans. Коммерческий шрифт в репозиторий не кладётся, поэтому сборка на чужой машине не ломается.
  - Знак валюты определяется по шрифту: если в нём нет U+20BD (в Mazzard, например, нет ни в одном начертании), в прайсе печатается «руб.» вместо «₽». Проверка через `fontkit.hasGlyphForCodePoint`.
  - Карта в PDF собирается из тайлов OpenStreetMap: тайлы кладутся в clip-прямоугольник со сдвигом, чтобы точка была в центре — так не нужна библиотека склейки картинок и API-ключ. Тайлы кэшируются на диск (`data/tiles`), запрос идёт с осмысленным User-Agent. Нет интернета — вместо карты подпись с координатами.
  - PDFKit не умеет webp: для фото в прайс берётся первый снимок в jpeg/png.
  - **Кнопка «Продать»** (главная кнопка панели) — продажа отмеченных экранов: окно «Продажа размещения» открывается с уже подставленными галочками из таблицы. Внутри: выбор клиента из списка **или кнопка «Новый клиент»**, которая раскрывает мини-форму (название, телефон, email) — после сохранения (`POST /clients`) клиент сразу подставляется в поле. Дальше менеджер, скидка, длительность ролика (общая, с правкой по каждому экрану), период, тайм-слот и статус кампании: **Продажа** (по умолчанию) / Бронь / Черновик. Живой пакетный расчёт через `/capacity/quote`: по каждому экрану цена и отметка «помещается / не помещается», в подвале число экранов и итог. Кнопка подписана по статусу («Продать», «Забронировать», «Создать черновик») и блокируется, пока есть непомещающиеся экраны (кроме черновика). Отправка — `POST /campaigns/bulk`, затем переход на карточку кампании.
  - Кнопка **«Добавить клиента»** — то же окно в режиме брони, без предвыбора экранов (статусы: Бронь / Черновик).
  - **Форма экрана** — многошаговая по секциям: Характеристики (код, название, **сторона**, тип, ориентация, статус) / Адрес и координаты / Технические параметры (размер, разрешение, шаг, яркость, длина блока, часы) / Финансы (ставка ₽ за 1 сек за 30 дней, налог) / Владелец и доп. (владелец, теги, комментарий) / **Карта и фото** (живой предпросмотр карты по введённым координатам + загрузка/удаление фотографий, назначение главного; для нового экрана — подсказка сохранить его перед загрузкой фото).
- **Продажи ▾**: Заказы/Кампании, Брони/Резервы, Платежи.
  - **Кампания (карточка)** — вкладки **Размещение / Креативы / Оплата**; кнопки смены статуса; сводные карточки (клиент, менеджер, размещение, производство, итого, оплачено).
  - **Добавление слота** — модалка с выбором экрана, длительности, периода, тайм-слота, ролика; **живая проверка ёмкости** и **калькулятор** с разбивкой цены; кнопка блокируется при переполнении активной кампании.
- **Контрагенты ▾**: Клиенты, Менеджеры, Владельцы экранов (CRUD).
- **Платежи** — реестр, суммы; платёж проводится из карточки кампании.
- **Настройки** (admin) — вкладки: Данные о компании (+ срок брони), **Мой аккаунт** (имя, email-логин, смена пароля; поле «Текущий пароль» появляется только когда меняется email или пароль; после сохранения токен сессии обновляется через `setAuth`), Города/области, Типы экранов, Тайм-слоты (с коэф.), Скидки, Налоговые режимы.
- **Менеджеры** — не универсальный справочник, а своя страница: колонка «Вход в систему» показывает логин либо «нет доступа», в форме отдельный блок «Доступ в систему» с логином и паролем (минимум 6 символов, занятый логин → 409). Кнопки правки и удаления видит только администратор.

## 9. Окно занятости экрана (открывается по клику на название экрана в инвентаре) — ВАЖНАЯ ФИЧА

Модальное окно, вид «сетка занятости, как у билбордов, но по блоке»:

1. **Шапка экрана** — плашка из 4 сегментов через разделители: `г. {город} | {адрес} | {сторона} | {код}`.
2. **Сетка занятости по месяцам** — строки = клиенты (сгруппированы по client_id из активных слотов года), столбцы = 12 месяцев (янв…дек). У каждого клиента синяя полоса, растянутая от месяца начала до месяца конца слота (клип по границам года). Клик по полосе открывает карточку кампании. В левом верхнем углу сетки — кнопка **«+»**.
3. **Кнопка «+»** открывает окно **«Добавить клиента на экран»**: выбор клиента, длительность ролика, выходов/сутки, период, тайм-слот; живая проверка ёмкости блока и расчёт стоимости; по подтверждению → `POST /screens/:id/book` (создаёт кампанию-бронь + слот), сетка обновляется.
4. **Полоса загруженности за выбранный месяц** (под сеткой): **месяцы в сетке кликабельны** — по клику на месяц полоса показывает загрузку экрана **именно за этот месяц**. По умолчанию выбран текущий месяц; выбранный месяц подсвечивается, его колонка выделяется. Полоса: заголовок «Загрузка экрана — {месяц} {год}», процент заполнения блока, сегменты по клиентам (ширина = duration_sec/loop), подпись «занято X сек» / «свободно N / loop сек». Если в месяце нет размещений — «Блок свободен».
   - Расчёт за месяц считается **на клиенте** из `slots`: перебрать дни месяца, найти пиковый день (макс. суммарная занятость), сегменты сгруппировать по клиентам.
5. **Блок «Карта и фото»** под лентой загрузки: слева карта расположения экрана, справа галерея фотографий (главное фото крупно + миниатюры, клик — просмотр во весь экран). Карта — встраиваемый iframe OpenStreetMap по координатам экрана (`https://www.openstreetmap.org/export/embed.html?bbox=…&marker=lat,lng`, без API-ключа и без внешних библиотек) плюс ссылки «Яндекс / 2ГИС / OSM». Если координат нет — вместо карты подсказка их заполнить.
6. Внизу — переключатель года (‹ пред · {год} · след ›).

## 11. Порядок реализации

## 12. Критерии приёмки

- Нельзя забронировать/продать при переполнении блока (в т.ч. собственными роликами кампании) — 409 с внятным сообщением; отмена освобождает ёмкость; просроченные брони снимаются автоматически.
- Калькулятор корректно учитывает секунды × выходы × дни × коэф. тайм-слота − скидка (+НДС сверху).
- Мультитенантность: менеджер не видит чужой тенант; менеджеру запрещены операции с экранами и удаление платежей.
- Клик по названию экрана открывает окно занятости; клик по месяцу меняет полосу загрузки на этот месяц; «+» бронирует клиента и обновляет сетку.
- Русский UI, ₽, даты ДД.ММ.ГГГГ.
