# LED-List — SaaS для операторов цифровой наружной рекламы (DOOH)

Мультитенантная система управления сетью LED-экранов. В отличие от систем для статичных билбордов, рекламное место продаётся не «поверхность на месяц», а **слот в петле ротации**: длительность ролика × количество выходов × период трансляции × тайм-слот.

## Запуск

```bash
# API (порт 3001)
cd server && npm install && npm run dev

# Клиент (порт 5173, проксирует /api на 3001)
cd client && npm install && npm run dev
```

База (SQLite, `server/data/led.db`) создаётся и наполняется демо-данными при первом старте. Чтобы сбросить — удалите файл БД.

## Архитектура

- **client/** — React 18 + TypeScript + Vite, роутинг react-router, без UI-библиотек (собственные стили админ-панели).
- **server/** — Node/Express + TypeScript (tsx), better-sqlite3. Схема БД переносима на PostgreSQL (целочисленные PK, FK, CHECK-ограничения).
- Мультитенантность: каждая строка бизнес-данных несёт `tenant_id`; все запросы фильтруются по тенанту из JWT.
- Роли: `superadmin` (управление подписками), `admin` (всё в рамках компании), `manager` (продажи; создание/правка экранов и удаление платежей запрещены).
- Креативы: загрузка mp4/jpg/png/gif (multer → `server/data/uploads/`); разрешение и длительность считываются в браузере при загрузке.

## Ключевая бизнес-логика (server/src/engine.ts)

**Движок ёмкости петли.** Экран крутит петлю длиной `loop_duration_sec`. Активный слот (кампания в статусе «Бронь»/«Продано») занимает `duration_sec` секунд петли каждый день периода `date_from…date_to`. Для любого дня: `Σ длительностей активных роликов ≤ длина петли`.

- `loopLoad()` — посуточная загрузка петли в % (используется в инвентаре, карточке экрана, при подборе слота);
- `checkCapacity()` — влезет ли ролик на всём периоде (для добавления слота);
- `checkCampaignCapacity()` — агрегатная проверка всех слотов кампании при переходе в «Бронь»/«Продано» (учитывает, что несколько роликов одной кампании суммируются);
- `expireReservations()` — автоснятие просроченных броней (освобождает ёмкость).

**Статусы кампании:** Черновик → Бронь (держит ёмкость N дней, срок в настройках) → Продано; Отмена на любом шаге освобождает петлю. Переходы валидируются на сервере, при активации — проверка ёмкости с HTTP 409 при переполнении.

**Калькулятор:** `цена = ₽/сек × длительность × выходов/сутки × дней × коэф.тайм-слота − скидка% (+ НДС, если режим с налогом сверху)`. Если у экрана задана только цена за выход, она трактуется как цена 5-секундного выхода.

## Разделы

- **Инвентарь экранов** — таблица с загрузкой петли в % за выбранный диапазон дат, настраиваемые колонки, модальный фильтр с несколькими условиями (код, город, тип, шаг пикселя, владелец, загрузка ≥/≤, теги…), форма экрана по секциям (Характеристики / Адрес и координаты / Технические параметры / Финансы / Владелец), предпросмотр плейлиста и посуточная шкала занятости.
- **Заказы / Кампании** — список со статусами и оплатой; карточка с вкладками Размещение / Креативы / Оплата; добавление слота с живой проверкой ёмкости и калькулятором.
- **Брони / Резервы** — активные брони со сроком удержания.
- **Клиенты / Менеджеры / Владельцы** — справочники контрагентов.
- **Платежи** — реестр поступлений (проводятся из карточки кампании).
- **Подписки** — тенанты платформы (только суперадмин): регистрация, срок действия, блокировка.
- **Настройки** — данные компании, срок брони, справочники: города/области, типы экранов, тайм-слоты (с коэффициентами цены), скидки, налоговые режимы.

## API (основное)

```
POST /api/auth/login
GET  /api/screens?from&to              # инвентарь + загрузка петли за период
GET  /api/screens/:id/availability     # посуточная загрузка
GET  /api/screens/:id/playlist?date    # ротация на дату
POST /api/capacity/check               # проверка «влезет ли ролик»
POST /api/calc/price                   # калькулятор стоимости слота
POST /api/campaigns/:id/slots          # добавить слот (409 при переполнении активной кампании)
POST /api/campaigns/:id/status         # переходы draft/reserved/sold/cancelled
POST /api/campaigns/:id/creatives      # загрузка ролика (multipart)
GET|POST /api/{clients,managers,owners,payments,cities,screen-types,time-slots,discounts,tax-regimes,tenants}
```
